# PickXtimes Dual-Memory Experiment

This note records the course-project experiment focused on the RoboMME
`PickXtimes` counting task.

## Goal

The task requires the robot to repeat pick/place actions a specified number of
times and then press the button to stop. The project studies whether combining
symbolic memory and perceptual memory can reduce counting failures.

## Compared Settings

- `symbolic_groundedSG_oracle`: symbolic grounded subgoals from the simulator
  oracle.
- `symbolic-grounded-subgoal + QwenVL`: symbolic grounded subgoals generated by
  Qwen3-VL.
- `perceptual-framesamp-modul`: perceptual frame-sampling memory with modulation.
- `dual-correction-stale-500`: dual memory initialized from the symbolic and
  perceptual checkpoints, with a lightweight correction gate.

## Dual-Memory Design

The dual model keeps symbolic grounded subgoals in the prompt path and adds
perceptual frame-sampling memory through the modulation path. A token-wise
correction gate controls how much the perceptual latent memory changes the
expert hidden state.

The dual model is initialized from:

- symbolic checkpoint: `runs/ckpts/mme_vla_suite/symbolic-grounded-subgoal/79999`
- perceptual checkpoint: `runs/ckpts/mme_vla_suite/perceptual-framesamp-modul/79999`

Only the correction adapters are fine-tuned:

- `mem_attn`
- `mem_rms_norm`
- `mem_correction_gate`

The perceptual encoder and the VLA backbone remain frozen.

## Stale Symbolic Augmentation

During dual-memory fine-tuning, symbolic subgoals are randomly replaced with
previous subgoals from the same episode. This simulates the failure mode observed
with QwenVL, where the symbolic subgoal can become stale and repeat an already
executed count.

## PickXtimes QwenVL Fallback

For online evaluation, the fallback controller parses the stage implied by the
QwenVL subgoal:

- `pick1`, `place1`, `pick2`, `place2`, ...
- final `stop`

Normally QwenVL remains the symbolic-memory source. The controller intervenes
only when the candidate is unparseable, stale, or stuck for too long. In the
verifier version, a second QwenVL call receives recent execution frames and
chooses between:

- continue the current subgoal
- move to the next subgoal if visually completed

This avoids blindly advancing the count on a timeout.

## Useful Commands

Fine-tune the dual correction model:

```bash
NUM_TRAIN_STEPS=500 EXP_NAME=dual-correction-stale-500 DATASET_PATH=data/robomme_preprocessed_data_sample GPU_ID=0 bash scripts/finetune_dual_memory_correction.sh
```

Evaluate QwenVL symbolic memory on PickXtimes:

```bash
MAX_EPISODES_PER_TASK=20 COUNTING_TASKS=PickXtimes MODEL_TYPE=symbolic_groundedSG_oracle GPU_ID=0 PORT=8014 bash scripts/eval_counting_single_gpu.sh
```

Evaluate the dual correction checkpoint with QwenVL fallback:

```bash
XLA_PYTHON_CLIENT_MEM_FRACTION=0.62 MAX_EPISODES_PER_TASK=20 COUNTING_TASKS=PickXtimes MODEL_TYPE=dual_correction_stale_500_fallback_qwenvl CKPT_ID=499 GPU_ID=0 PORT=8015 EXTRA_ARGS="--args.only-episodes=2,3,12 --args.progress-pick-timeout-steps=96 --args.progress-place-timeout-steps=96 --args.progress-stop-timeout-steps=64" bash scripts/eval_counting_single_gpu.sh
```

## Observed Results

On the 20-episode PickXtimes QwenVL symbolic-memory run, the main failures were
episodes `2`, `3`, and `12`.

With the dual correction checkpoint and QwenVL fallback:

- episode `2` was fixed
- episode `3` reached the stop stage but still failed, likely due to low-level
  execution
- episode `12` exposed the key failure mode: QwenVL repeatedly produced a stale
  pick subgoal. Hard timeout fallback can advance the symbolic stage, but may be
  premature. The perceptual verifier correctly held the stage when the visual
  evidence suggested the current pick was not complete.

## Current Conclusion

The experiment supports the following interpretation:

1. QwenVL symbolic memory is useful but can drift or repeat stale counting
   subgoals.
2. Perceptual memory is most useful as a verifier or correction signal, not as a
   replacement for symbolic memory.
3. Extra VLM-based verification is too slow for full evaluation.
4. A better final system would train a lightweight perceptual progress verifier
   from latent memory, replacing the extra QwenVL revision call.
